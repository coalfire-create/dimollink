# kb_sources — RAG 안전지침 원문

디몰비전 RAG 지식베이스(§3.4)의 원문 소스. 여기 파일들을 청킹·임베딩해 `kb_documents` 에 적재한다.

## 포맷

`*.md` / `*.txt`. 상단 front matter + `## <조항>` 헤더로 조항을 구분한다:

```
---
source: <출처 문서명>
revised_at: <YYYY-MM-DD>   # 선택
---

## 제5조(해체작업계획서)
본문...
```

- `source`, `clause`(헤더), `body` 가 그대로 `kb_documents` 로 들어간다.
- 조항 본문이 길면 자동으로 창 분할(기본 800자, overlap 100자).

## 적재 체크리스트 (기획서 §3.4)

리포트의 안전지침은 **여기 적재된 문서만** 인용할 수 있다(아래 "인용 강제" 참고).
KB 가 비면 안전지침이 통째로 사라지므로, 실운영 전 아래를 모두 채워야 한다.

| # | 문서 | 출처 | 상태 |
|---|---|---|---|
| 1 | KOSHA GUIDE 해체공사 안전보건작업 지침 | 안전보건공단 KOSHA GUIDE 자료실 | ⛔ 샘플 발췌만 |
| 2 | 산업안전보건기준에 관한 규칙 — 구축물 해체 관련 조항 | 국가법령정보센터 | ⛔ 미적재 |
| 3 | 건축물관리법·시행령 — 해체계획서·해체공사 감리 | 국가법령정보센터 | ⛔ 미적재 |
| 4 | 석면안전관리법·시행규칙 — 사전조사·해체제거 절차 | 국가법령정보센터 | ⛔ 미적재 |
| 5 | 건설폐기물의 재활용촉진에 관한 법률 — 분리배출 기준 | 국가법령정보센터 | ⛔ 샘플 발췌만 |
| 6 | 폐기물관리법 — 지정폐기물(석면) 처리 기준 | 국가법령정보센터 | ⛔ 미적재 |

적재할 때 지킬 것:

1. **조문 번호를 정확히** `## 제N조(제목)` 헤더로 넣는다 — 그대로 `source_clause` 로 인용된다.
2. `source` 는 문서 정식 명칭. 리포트에 그대로 노출되므로 축약·의역하지 않는다.
3. 요약하지 말고 **조문 원문**을 넣는다. 요약을 원문으로 인용하면 잘못된 근거가 된다.
4. 법령 개정 반영을 위해 **분기 1회 갱신**하고 `revised_at` 을 함께 고친다.

## 인용 강제 (환각 차단)

- 2패스 생성이 내놓은 안전지침 중 **검색된 근거의 `source_document` 와 일치하지 않는 항목은
  후처리에서 버린다**(`app/pipeline/vllm.py::_enforce_safety`). 프롬프트로 "근거만 인용하라"고
  시켜도 모델은 그럴듯한 출처를 지어낸다.
- `source_document` 가 빈 안전지침은 검증 레이어가 리포트 전체를 실패시킨다
  (`app/validation.py`, `packages/shared/vision-report.ts`).
- 즉 **근거 없는 안전지침은 절대 사용자에게 도달하지 않는다.** 대신 KB 가 부실하면
  공정표에 안전지침이 비어 나오므로, 위 체크리스트를 채우는 것이 곧 리포트 품질이다.

## ⚠️ 현재 상태

지금 있는 파일은 **파이프라인 검증용 샘플 발췌**다(`source` 에 "(샘플 발췌)" 표기).
상용 적재 전 위 체크리스트대로 공식 원문·정확한 조문 번호로 교체한다.

## 적재

```bash
# 목 임베딩으로 JSONL 검사(로컬)
python scripts/ingest_kb.py --sources-dir kb_sources --out kb_chunks.jsonl

# 실제 BGE-M3 → Postgres (kb extra 필요)
pip install '.[kb]'
python scripts/ingest_kb.py --embedder bge-m3 --dsn "$SUPABASE_DB_URL"
```
