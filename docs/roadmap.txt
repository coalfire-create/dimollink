디몰링크 개발 로드맵
기획서 원안 + 7/1 개선안 전체 통합 · 2026.07.02 기준
1. 개요
디몰링크는 철거 업체, 운반 업체, 폐기물 처리장을 연결해 비교·견적·연결·기록을 한 번에 처리하는 매칭 플랫폼이다. 핵심 차별점은 환경부 올바로시스템과의 API 연동으로, 회원 검증부터 전자인계서 발행, 처리 실적 반영까지 사용자가 올바로에 별도로 로그인하지 않아도 되도록 자동화하는 데 있다.
이 로드맵은 원 기획서의 요구사항과 7/1 개선안에서 제시된 매칭/가격, 신뢰/검증, 결제/정산, 알림/커뮤니케이션, 운영/관리자, 올바로 연동 안정성, 접근성 항목을 하나도 빠짐없이 반영하고, 우선순위와 기술적 의존관계에 따라 Phase 0~6으로 재배열한 것이다. 기간은 1인 개발 기준의 러프한 추정치이며, 실제 범위 확정 후 조정이 필요하다.

3. Phase 0 — 기반 설계 (착수 전)
개발 착수 전에 리스크를 먼저 확인하고 숫자로 된 완료 기준을 채우는 단계. 문서 작업이 아니라 실제 검증이 핵심이다. 아래 5개 항목이 모두 채워진 시점이 Phase 1 착수 시점이다.
3.1 경쟁사 벤치마킹
국내 유사 서비스인 "빼기(Bbegi)", "폐기노트"를 1~2일 내로 직접 가입해 사용해본다. 확인 항목: 운반업체 매칭 기능 유무, 가격 노출 방식, 올바로 연동 여부. 두 서비스 모두 배출 신고 중심의 단방향 구조로 예상되며, 이 가설이 맞다면 디몰링크의 3자 매칭 + 올바로 연동이 확실한 차별점이 된다.
3.2 공급 측(운반업체·처리장) 사전 확보
대표(기획자)의 기존 업계 인맥을 활용해 운반업체 5곳, 처리장 3곳을 사전 확보한다. "이야기해봤다"가 아니라 "앱이 나오면 쓰겠다는 구두 확답을 받은 곳"을 기준으로 삼는다. 이 숫자가 채워지기 전에는 본격 개발 착수를 보류하는 것을 권장한다 — 공급자 없는 앱은 배출자도 붙지 않는다.
3.3 올바로 API 연동 신청 (진행 확정)
올바로 오픈API 연동을 하는 것으로 확정했다. 사업자등록 형태(개인/공동사업자/법인)를 먼저 확정한 뒤, 1644-0007로 전화해 "민간 플랫폼의 회원 검증·전자인계서 자동생성·실적 연동 API 연동 절차"를 구체적으로 문의한다. 확인할 것: 승인 소요기간, 사업자등록증 외 추가 서류, 연동 심사 기준. 서류가 준비되는 대로 최대한 빨리 신청서를 접수한다 — 정부기관 연동이라 승인 기간이 전체 일정을 좌우하는 변수다.
3.4 결제·정산 정책 확정
에스크로 대신 선결제 방식으로 단순하게 시작한다. 배출자가 매칭 확정 시점에 선결제하고, 플랫폼 수수료 7%를 제한 나머지를 운반업체/처리장에 익영업일(D+1) 정산한다. 세금계산서는 정산 시점에 자동 발행되도록 설계한다. 서비스가 안정화된 뒤 수수료율과 정산 구조(에스크로 전환 등)를 재검토한다.
3.5 파일럿 지역 · 카테고리 확정
파일럿 지역은 양평으로 확정한다. 폐기물 카테고리는 기획서에 이미 언급된 건설폐기물(철거현장) 5톤 이상 구간으로 한정한다. 이 조합이 올바로 의무 신고 대상과 겹쳐서, 올바로 연동이라는 차별점을 파일럿에서부터 가장 강하게 체감시킬 수 있다. 3.2의 운반업체·처리장 확보도 양평 권역을 우선순위로 진행한다.
4. Phase 1 — MVP
실제 서비스가 굴러가기 위한 최소 기능. 올바로 연동은 디몰링크의 핵심 차별점이므로 MVP에서 빠질 수 없고, 결제/정산은 개선안에서 필수 설계 항목으로 지적되었으므로 최소 형태로라도 MVP에 포함한다.

6. Phase 3 — 매칭 알고리즘 고도화
거래 데이터가 일정량 쌓여야 의미 있는 항목들이라 신뢰 구축 이후로 배치한다.
실시간 가격비교 알고리즘: 단순 거리순이 아니라 거리+가격+평점 가중치 조합 추천 정렬

  [개선안·매칭가격]
자동매칭 타임아웃/재매칭: 운반업체가 일정 시간 내 미응답 시 다음 업체로 자동 전환

  [개선안·운영관리자]

  [개선안·운영관리자]
9. Phase 6 — 안정성 · 접근성 · AI 고도화
올바로 API 장애/타임아웃 폴백 고도화: 자동 전환 + 나중에 재시도 큐 처리
  [개선안·올바로 연동 안정성]
전자인계서 발행 실패 건에 대한 관리자 알림 및 수동 재처리 화면

  [개선안·신뢰검증]

  [개선안·접근성]
10. 우선순위 판단 근거
올바로 연동과 최소 결제 기능을 Phase 1에 넣은 이유는, 올바로 연동이 기획서상 핵심 차별점이자 서비스의 존재 이유이고, 결제/정산은 개선안에서 "기획서에 아예 언급이 없다"고 지적된 만큼 뒤로 미룰수록 설계를 다시 갈아엎을 위험이 크기 때문이다.
리뷰·인증·시세정보(Phase 2, 3)는 실제 거래 데이터가 쌓여야 값어치가 생기는 기능이라 MVP 이후로 배치했다. 매칭 자체가 안 되는 상태에서 평점 시스템부터 만들면 채울 데이터가 없다.
커뮤니케이션 강화, 운영 도구, AI/접근성 고도화(Phase 4~6)는 사용자 수가 늘어나면서 운영 리스크 관리와 사용 경험 개선 차원에서 필요해지는 항목들이라 후순위로 두었다. 다만 이상거래 탐지나 올바로 API 폴백처럼 리스크가 큰 항목은 사용자가 늘기 전에 앞당겨도 무방하다.
