# 디몰비전 개발 현황 (로드맵 V0~V5 대비)

기준: `docs/디몰비전_AI_시스템_기획서.docx` v1.1. 브랜치 `feature/vision-subsystem`.
범례: ✅ 코드 완료(검증) · 📄 문서/설정 · ⛔ 하드웨어·비즈니스 게이트(자율 불가).

> **요약:** 코드로 완결 가능한 전 범위(공유 계약, AI 서버, 웹, Supabase, RAG, 평가, 개인정보,
> 프리필, 플라이휠, 모니터링)를 구현·검증했다. 남은 것은 **GPU 실추론·파인튜닝, 실데이터 수집·라벨링,
> AI Hub 승인·자문계약, 실배포·파일럿** 뿐이며, 이는 하드웨어/외부기관/현장이 필요해 코드로 대체할 수 없다.

## 촬영 프로토콜 (§4.3, V2 수집 표준)
- 현장당 20~40장. 외부 4방향(전/후/좌/우), 내부 실별, 지붕재 근접.
- 준공 연도·연면적·층수·용도를 부가 입력으로 함께 기록.
- 개인정보(번호판·인물·주소 표지)는 수집 즉시 블러(`app/media`), EXIF(GPS) 제거 기본.
- 촬영 협조는 매칭 수수료 할인 등 인센티브와 연동. 초기 목표 50현장(1,000~2,000장).

## 검증 상태
- `apps/vision-api`: **pytest 45개 통과**(.venv). Edge Functions: esbuild 문법 검증(Deno 미설치 실행 미검증).
- `packages/shared`: typecheck + 런타임 검증 통과.
- `apps/vision-web`: node --check + mock 흐름 하네스 통과.

## 남은 실행(비코드) 체크리스트
1. GPU 인스턴스 확보 → `VISION_PIPELINE=vllm` 실추론 검증, FP8/AWQ 서빙
2. AI Hub 데이터셋 승인 + 양평 현장 촬영·라벨링 → QLoRA 학습 → `scripts/eval.py` 통과
3. Supabase 프로젝트 생성 → 마이그레이션·Edge Function 배포 → vision-web 실백엔드 전환
4. 협력 철거업체 자문계약(공정표 정답 데이터)
5. 본체 매칭·올바로 연동 완성 확인 후 프리필 활성화(§10)
6. git 원격 추가 → `feature/vision-subsystem` push / PR
