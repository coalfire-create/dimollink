# 디몰링크 상용화 배포 런북

상용 런치를 위한 인프라 프로비저닝 + 배포 절차. 코드는 배포 준비 완료 상태이며, 아래는 **계정·서비스 프로비저닝 + 환경변수 주입**이 핵심이다.

> 원칙(CLAUDE.md): 민감정보는 각 플랫폼의 환경변수(Secret)에만 넣고 코드/커밋에 남기지 않는다. 올바로·PG는 반드시 샌드박스/테스트로 검증 후 운영 전환한다.

---

## 1. 호스팅 구조

- **API(Express)**: Vercel 서버리스로 배포. 엔트리 `api/index.js`(→ `apps/api/dist/app.js`), 설정 `vercel.json`.
  - 빌드: `npm run build:shared && npm run build -w @dimol/api`(vercel.json에 정의됨).
  - 서버리스 제약상 세션·OTP·레이트리밋은 **Upstash Redis(REST)** 또는 `SESSION_SECRET`(무상태)로 공유해야 한다(인메모리는 인스턴스마다 초기화됨).
- **랜딩/웹**: 현재 `디몰링크.com` → Netlify `demolink-app`. 유지하거나 Vercel로 일원화.
- **API 도메인**: `api.디몰링크.com` 서브도메인을 Vercel 프로젝트에 연결(CNAME).

## 2. 프로비저닝 체크리스트 (님 계정 필요)

| 서비스 | 용도 | 주입 환경변수 |
|---|---|---|
| **PostgreSQL** (Neon / Vercel Postgres) | 영속 저장(회원·요청·결제·정산) | `DATABASE_URL` |
| **Upstash Redis** (REST) | 세션·OTP·레이트리밋 공유(서버리스) | `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` |
| **S3 / NCP Object Storage** | 현장 사진(비공개 버킷, presigned) | `STORAGE_BUCKET`, `STORAGE_ACCESS_KEY_ID`, `STORAGE_SECRET_ACCESS_KEY`, (호환 시 `STORAGE_ENDPOINT`) |

> DB 스키마는 별도 마이그레이션 불필요 — `pg-collection`이 최초 연결 시 `entities` 테이블을 자동 생성한다. (정규화 스키마가 필요해지면 후속 마이그레이션 도입)

## 3. 운영 환경변수 (Vercel Project → Settings → Environment Variables)

**필수 (없으면 기동/보안 문제)**
```
NODE_ENV=production
CORS_ORIGINS=https://디몰링크.com,https://www.디몰링크.com   # 운영은 반드시 지정
SESSION_SECRET=<강한 랜덤 32B+>                              # Upstash 없을 때 세션 유지
ADMIN_TOKEN=<강한 랜덤>                                       # 미설정 시 /api/admin/* 503 잠금
DATABASE_URL=...                                             # 영속화(미설정 시 데이터 휘발)
UPSTASH_REDIS_REST_URL=... / UPSTASH_REDIS_REST_TOKEN=...
```

**인증/알림·결제·연동** (각 절차 완료 후)
```
# SMS(Solapi): 계정 IP 허용 + 발신번호 등록 후
SMS_PROVIDER=solapi  SOLAPI_API_KEY=...  SOLAPI_API_SECRET=...  SMS_SENDER=<등록발신번호>
# 소셜 로그인: 공급자 콘솔 등록 후
OAUTH_REDIRECT_BASE=https://api.디몰링크.com  OAUTH_APP_REDIRECT=dimollink://auth  OAUTH_STATE_SECRET=<랜덤>
KAKAO_CLIENT_ID/SECRET, GOOGLE_CLIENT_ID/SECRET, NAVER_CLIENT_ID/SECRET
# 결제(PortOne): 테스트 검증 완료 후 운영 전환 시에만 live
PORTONE_API_SECRET=...  PORTONE_STORE_ID=...  PORTONE_WEBHOOK_SECRET=...
PORTONE_ENV=test        # 실거래 준비 완료 전까지 test 유지, 전환 시 live + PORTONE_ALLOW_LIVE=true
# 올바로: 샌드박스 검증 완료 후에만 production
ALLBARO_API_BASE_URL=...  ALLBARO_API_KEY=...  ALLBARO_ENV=sandbox
```

> ⚠️ 세션에서 채팅으로 노출된 키(PortOne API Secret·웹훅, Solapi)는 **운영 투입 전 재발급**해서 넣을 것.

## 4. 배포 절차

```bash
# 로컬 사전 점검
npm run build:shared && npm run build -w @dimol/api    # API 빌드
npm run typecheck -w @dimol/mobile                     # 앱 타입체크
npm test --workspaces --if-present                     # 테스트

# Vercel 배포 (프로젝트 링크된 상태)
vercel --prod
```
- 배포 후 Vercel 대시보드에서 `api.디몰링크.com` 도메인 연결.

## 5. 배포 후 스모크 테스트

```bash
curl https://api.디몰링크.com/api/health           # 200
# OTP 발송 → 검증 → 회원가입 → 로그인 흐름 1건
# PortOne 웹훅 수신 확인(결제알림 관리에 운영 URL 등록: /api/payments/webhook)
```

## 6. 운영 준비 (부가)

- 모니터링: `deploy/monitoring/`(Prometheus·Alertmanager) 상시화, 또는 Sentry 연동.
- 백업: `deploy/scripts/pg-backup.sh` 정기 실행(cron).
- 웹훅 URL 등록: PortOne 결제알림 관리 → `https://api.디몰링크.com/api/payments/webhook`.
