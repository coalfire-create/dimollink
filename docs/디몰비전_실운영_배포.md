# 디몰비전 실운영 배포 런북 (mock → 라이브)

지금 앱은 `config.mock=true` 라 예시 리포트를 낸다. 실제 AI 분석이 되려면 아래 **3개 다리**를
모두 세워야 한다. 코드는 완성·검증됐고, 남은 건 **인프라 기동 + 크레덴셜 주입**뿐이다.

```
[vision-web]  →  [Supabase: Auth·Storage·DB·Edge·Realtime]  →  [vision-api (GPU, vLLM+LoRA)]
   (정적호스팅)        (① 프로젝트 배포)                          (② GPU 서빙)
```

> ⚠️ **자율 불가 지점(사람 필요):** ① Supabase 프로젝트 소유·토큰, ② GPU 상시 과금 승인.
> 이 두 값만 주면 아래 절차로 30분~1시간 내 라이브 가능.

---

## ① Supabase 프로젝트 배포

**필요 입력:** Supabase 계정, 새 프로젝트(ref), DB 비밀번호, 액세스 토큰.

```bash
# CLI 준비
brew install supabase/tap/supabase
supabase login                                   # 액세스 토큰

# 시크릿 작성(.env.example 복사 후 값 채움) — VISION_API_URL/KEY 등
cp apps/vision-api/supabase/.env.example apps/vision-api/supabase/.env
$EDITOR apps/vision-api/supabase/.env

# 한 방 배포: 스키마(0001~0003) + Edge Functions + 시크릿
cd apps/vision-api
PROJECT_REF=<프로젝트ref> ./scripts/deploy_supabase.sh
```

`deploy_supabase.sh` 가 하는 일: `supabase link` → `db push`(0001 init·0002 rls·**0003 storage 버킷+정책**)
→ `functions deploy`(sign-upload·create-analysis·analysis-callback, 콜백만 `--no-verify-jwt`) → `secrets set`.

**대시보드 확인:** Authentication 활성(이메일/전화), Storage 에 `vision-site-photos` 버킷 생성됨,
`analyses` 테이블 Realtime 활성(Database → Replication).

## ② GPU 서빙 (vision-api, vLLM + LoRA)

**필요 입력:** GPU 인스턴스(L4 24GB↑) — 상시 과금. 이미 GCP 학습에 쓰던 계정 사용 가능.
어댑터 `dist/recognition-ground-v2.zip`(학습 완료본).

절차 전체는 `apps/vision-api/training/SERVING.md`. 요지(L4 = fp8 필수):

```bash
# GPU VM 에서
python3 -m vllm.entrypoints.openai.api_server \
  --model Qwen/Qwen3-VL-8B-Instruct --enable-lora \
  --lora-modules recognition-ground-v2=<어댑터경로> --max-lora-rank 16 \
  --quantization fp8 --kv-cache-dtype fp8 \
  --max-model-len 3072 --enforce-eager --gpu-memory-utilization 0.95 --port 8000

# 같은 VM(또는 별도)에서 FastAPI 잡 서버
VISION_PIPELINE=vllm \
VISION_VLLM_BASE_URL=http://<vllm-host>:8000/v1 \
VISION_VLLM_LORA=recognition-ground-v2 \
VISION_API_KEY=<Edge 와 공유> \
VISION_CALLBACK_SECRET=<Edge 와 공유> \
  uvicorn app.main:create_app --factory --host 0.0.0.0 --port 8080
```

- `VISION_API_URL`(Edge 시크릿) = 이 FastAPI 의 공개 주소 `https://.../v1`.
- `VISION_API_KEY`·`VISION_CALLBACK_SECRET` 는 **Edge 와 vision-api 가 동일 값**이어야 한다.
- KB(RAG)를 pg 로 쓰려면 `VISION_KB_BACKEND=pg` + `VISION_DB_URL`(Supabase) + `scripts/ingest_kb.py` 적재.

## ③ vision-web 실백엔드 전환 + 호스팅

`apps/vision-web/config.js` 를 프로덕션 값으로:

```js
window.DimolVision.config = {
  mock: false,                                  // ← 실백엔드
  supabaseUrl: "https://<프로젝트ref>.supabase.co",
  supabaseAnonKey: "<anon 공개키>",             // 공개 가능(RLS 로 보호)
  maxPhotos: 40,
  maxBytesPerPhoto: 10 * 1024 * 1024,
};
```

정적 호스팅(Vercel 등)에 `apps/vision-web/` 배포. anon 키는 공개 가능값(RLS 가 실제 방어).

## 스모크 테스트 (라이브 검증, §종료기준)

1. 웹 접속 → 로그인 → 현장 사진 여러 장 업로드 → "분석 시작".
2. Storage `vision-site-photos/<user_id>/...` 에 업로드됨 확인.
3. `analyses` 행 생성 → status `queued`→`processing`→`done` 진행(Realtime 로 화면 갱신).
4. 리포트에 자재/석면/**예상 철거 공정**/폐기물·올바로 표시, 하단 고지 노출.
5. "이 분석 평가하기" 별점·교정 제출 → `feedback` 행 생성 확인(플라이휠 원천).
6. p95 지연 2분 이내(§종료기준) 확인.

## 롤백 / 운영

- 어댑터 롤백·교체: `POST /admin/reload` + `VISION_VLLM_LORA` 전환(무중단 AB).
- GPU 비용 절감: 야간/저부하 시 VM 중지(잡 큐는 재시도). 상시 필요 없으면 온디맨드.
- 재학습 루틴: 피드백 축적 → `scripts/export_feedback.py` → `scripts/retrain_cycle.py --from-db --gpu`
  → 평가 게이트 통과 시 `deploy_manifest.json` → `/admin/reload`.
