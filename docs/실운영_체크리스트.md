# 디몰링크(비움) 실운영 체크리스트

실제 사용자를 받기 전에 반드시 끝내야 할 항목과 방법. 위에서부터 순서대로 처리하면 된다.
`✅ 완료` 는 코드/검증이 끝난 것, `⬜ 필요` 는 사람이 계정·키·계약을 처리해야 하는 것이다.

---

## 0. 지금 상태 요약

| 영역 | 상태 |
|---|---|
| 요청 접수 → 업체 수신 → 견적 → 매칭 | ✅ E2E 검증 완료 |
| 정산 계산(수수료 7% · D+1 영업일 · 셀러별 차감) | ✅ 검증 완료 |
| 디몰비전(주소 게이트 · 건축물대장 · 사진 분석) | ✅ 검증 완료 |

## 1. 필수 인프라

### 1-1. PostgreSQL ⬜ 최우선
파일 저장소(`.data/*.json`)는 컨테이너 재배포 시 **전부 사라진다**. Railway 재배포만 해도 회원·요청이 날아간다.

```
Railway 대시보드 → New → Database → Add PostgreSQL
→ 생성된 DATABASE_URL 을 API 서비스 Variables 에 복사
```
설정하면 기동 로그가 `저장소: PostgreSQL` 로 바뀐다. 테이블·인덱스는 첫 기동에 자동 생성된다.

### 1-2. Redis (선택, 인스턴스 2대 이상일 때 필수)
세션·OTP·레이트리밋을 인스턴스 간 공유한다. 1대로 운영하면 생략 가능.
```
Railway → New → Database → Add Redis → REDIS_URL 복사
```

### 1-3. 필수 환경변수 (없으면 운영 모드 기동 자체가 중단됨)
| 변수 | 값 | 설명 |
|---|---|---|
| `NODE_ENV` | `production` | |
| `CORS_ORIGINS` | `https://<서비스도메인>` | 콤마 구분. 미설정 시 기동 중단 |
| `ADMIN_TOKEN` | 랜덤 32자 이상 | 백오피스 보호. 미설정 시 기동 중단 |
| `DATABASE_URL` | Railway 자동 주입 | |
| `SESSION_SECRET` | 랜덤 32자 이상 | Redis 없이도 세션 유지 |

랜덤 값 생성: `openssl rand -hex 32`

### 1-4. 절대 켜면 안 되는 변수 (운영)
`ALLOW_TEST_OTP`, `SEED_TEST_ACCOUNTS`, `OTP_DEV_MASTER_CODE`
→ 인증코드 `123456` 으로 아무 번호나 로그인된다. **운영에서는 설정 자체를 지운다.**

## 2. 외부 서비스 발급

### 2-1. 공공데이터 건축물대장 (디몰비전 핵심) ⬜
디몰비전이 주소로 건물 정보를 확인하는 데 쓴다. **자세한 발급 절차는 아래 4장 참고.**
| 변수 | 값 |
|---|---|
| `VISION_BLDG_LEDGER_KEY` | data.go.kr 발급 인증키 |
| `BUILDING_REGISTRY_TIMEOUT_MS` | `10000` (기본값) |

### 2-2. 카카오 로컬 API (주소 검색·지도 핀) ⬜
없으면 목(mock) 주소만 뜬다. 실서비스에는 필수.
```
developers.kakao.com → 내 애플리케이션 → 애플리케이션 추가
→ 앱 키 → REST API 키 복사
→ 플랫폼 등록(Web) 에 서비스 도메인 추가
```
| 변수 | 값 |
|---|---|
| `KAKAO_REST_API_KEY` | REST API 키 |
| `GEOCODE_PROVIDER` | `kakao` |

> 건축물대장 조회는 카카오 지오코딩으로 법정동코드·지번을 먼저 얻는다.
> **카카오 키가 없으면 건축물대장도 조회되지 않는다.** 둘은 세트로 넣어야 한다.

### 2-3. 비전 AI (사진 분석) ⬜
우선순위대로 하나만 있으면 된다: **Groq(무료·카드 불필요) → Gemini(무료 티어) → Claude(유료)**.
전부 없으면 목(MOCK) 결과가 나가고 화면에 "참고(목) 분석"으로 표시된다.

| 공급자 | 변수 | 발급처 |
|---|---|---|
| Groq | `GROQ_API_KEY`, `GROQ_MODEL` | console.groq.com |
| Gemini | `GEMINI_API_KEY`, `GEMINI_MODEL` | aistudio.google.com |
| Claude | `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL` | console.anthropic.com |

`VISION_TIMEOUT_MS` 기본 30초. 사용자가 기다리는 화면이라 30초 이상으로 늘리지 말 것.

### 2-4. 포트원(PortOne) 결제·정산 ⬜
없으면 선결제가 `503 CONFIG_MISSING` 으로 막힌다(매칭까지는 정상 동작).
```
admin.portone.io → 결제연동 → V2
→ 상점 아이디(Store ID), API Secret 발급
→ 결제대행사 계약(가상계좌 + 카드) 연동
→ 웹훅 URL 등록: https://<도메인>/api/payments/webhook
→ 지급대행(파트너 정산) 신청 · 전자세금계산서 옵션 활성화
```
| 변수 | 테스트 | 운영 |
|---|---|---|
| `PORTONE_STORE_ID` | 테스트 상점 | 운영 상점 |
| `PORTONE_API_SECRET` | 테스트 시크릿 | 운영 시크릿 |
| `PORTONE_WEBHOOK_SECRET` | 콘솔 발급 | 콘솔 발급 |
| `PORTONE_ENV` | `test` | `live` |
| `PORTONE_ALLOW_LIVE` | (설정 안 함) | `true` |

> **순서 엄수(CLAUDE.md 규칙):** `PORTONE_ENV=test` 로 먼저 전 구간 검증 → 그 다음 `live` + `PORTONE_ALLOW_LIVE=true`.
> `PORTONE_ALLOW_LIVE` 를 안 켜면 코드가 실거래 호출을 거부한다(실수 방지 장치).

### 2-5. 올바로(Allbaro) 전자인계서 ⬜
```
환경부 올바로시스템(www.allbaro.or.kr) → 회원가입(사업자)
→ 전자인계서 API 이용 신청 → 공동인증서 등록
→ 샌드박스 계정 발급 요청
```
| 변수 | 설명 |
|---|---|
| `ALLBARO_API_BASE_URL` | 발급받은 엔드포인트 |
| `ALLBARO_API_CERT_KEY` | 인증키 |
| `ALLBARO_USER_ID` / `ALLBARO_PASSWORD` | 계정 |
| `ALLBARO_COMPANY_CODE` | 사업장 코드 |
| `ALLBARO_ENV` | `sandbox` → 검증 후 `production` |
| `ALLBARO_ALLOW_PRODUCTION` | 운영 전환 시에만 `true` |

미설정이어도 서비스는 돈다 — 자체 간이확인서 경로로 폴백하고 재시도 큐에 쌓인다.

### 2-6. SMS(OTP 인증번호) ⬜
없으면 인증번호가 **서버 콘솔에만 찍혀서 실제 가입이 불가능하다.**
```
solapi.com 가입 → 발신번호 등록(통신서비스 이용증명원 필요, 승인 1~2일)
→ API Key / API Secret 발급
```
| 변수 | 값 |
|---|---|
| `SOLAPI_API_KEY` / `SOLAPI_API_SECRET` | 발급값 |
| `SMS_SENDER` | 등록한 발신번호 (예: `0212345678`) |

### 2-7. 현장 사진 스토리지 (S3 호환) ⬜
```
AWS S3 또는 NCP Object Storage 에서 버킷 생성 (리전: ap-northeast-2)
→ 액세스 키 발급 → 버킷 CORS 에 서비스 도메인 허용
```
| 변수 | 값 |
|---|---|
| `STORAGE_BUCKET` | 버킷명 |
| `STORAGE_ACCESS_KEY_ID` / `STORAGE_SECRET_ACCESS_KEY` | 액세스 키 |
| `STORAGE_REGION` | `ap-northeast-2` |
| `STORAGE_ENDPOINT` | NCP 등 S3 호환일 때만 |

### 2-8. 소셜 로그인 (선택)
`KAKAO_CLIENT_ID/SECRET`, `NAVER_CLIENT_ID/SECRET`, `GOOGLE_CLIENT_ID/SECRET`,
`OAUTH_REDIRECT_BASE`, `OAUTH_APP_REDIRECT`, `OAUTH_STATE_SECRET`

## 3. 배포 전 최종 점검

```bash
npm run lint && npm run typecheck && npm test   # 전부 통과해야 함
npm run build -w @dimol/mobile                  # 웹 번들 재빌드(중요)
```
> 웹 화면을 고쳤으면 **반드시 모바일 번들을 다시 빌드**해야 한다.
> `apps/api/public/web` 에 복사된 번들이 실제 서비스되는 파일이다.

배포 후 확인:
```bash
curl https://<도메인>/api/health          # {"status":"ok"}
curl https://<도메인>/api/health/ready    # {"status":"ready"}
curl -I https://<도메인>/                 # Cache-Control: no-store (HTML)
```

### 운영 필수 확인 항목
- [ ] `ALLOW_TEST_OTP` · `SEED_TEST_ACCOUNTS` 가 **설정되어 있지 않은지** 확인
- [ ] `ADMIN_TOKEN` 이 추측 불가능한 랜덤 값인지
- [ ] `CORS_ORIGINS` 에 실제 도메인만 있는지 (`*` 금지)
- [ ] DB 백업 스케줄 (`deploy/scripts/pg-backup.sh`)
- [ ] 업체 승인 절차 담당자 지정 — 가입 업체는 `PENDING` 상태라 **관리자가 승인해야 일감을 받는다**

업체 승인 방법:
```bash
curl -X PATCH https://<도메인>/api/admin/users/<사용자ID>/approval \
  -H "x-admin-token: $ADMIN_TOKEN" \
  -H "content-type: application/json" \
  -d '{"status":"APPROVED"}'
```

## 4. 공공데이터 건축물대장 API 키 발급 (상세)

### 1) 회원가입
[www.data.go.kr](https://www.data.go.kr) → 회원가입 (개인/기업 모두 가능, 무료)

### 2) 활용 신청
1. 상단 검색창에 **`건축물대장`** 검색
2. **오픈API** 탭 선택
3. **국토교통부_건축물대장 정보 서비스** 선택
   - 코드가 쓰는 엔드포인트는 `apis.data.go.kr/1613000/BldRgstHubService/getBrTitleInfo` (건축HUB) 이다.
   - 목록에 `건축HUB건축물대장정보` 와 구버전이 함께 보이면 **`1613000` / `BldRgstHubService`** 로 표기된 쪽을 신청한다.
4. **활용신청** 버튼 클릭
5. 신청 양식:
   - 활용목적: `웹 사이트 개발` 또는 `앱 개발`
   - 상세: "철거 폐기물 매칭 플랫폼에서 현장 주소의 건축물 구조·용도·사용승인일 확인"
   - 필요한 **오퍼레이션(활용 API)** 에서 **건축물대장 표제부 조회(getBrTitleInfo)** 를 반드시 체크
   - 라이선스 동의 → 신청

### 3) 승인 · 키 확인
- **개발계정은 자동 승인**(즉시 사용 가능). 트래픽은 보통 **일 1,000건**.
- 마이페이지 → **데이터활용 → Open API → 개발계정 → 신청한 서비스 클릭**
- **일반 인증키(Encoding)** 와 **일반 인증키(Decoding)** 두 개가 보인다.

### 4) 환경변수 설정
```
VISION_BLDG_LEDGER_KEY=<복사한 인증키>
```
> **Encoding / Decoding 어느 쪽을 넣어도 동작하도록 코드에서 처리한다**(`encodeServiceKey`).
> 굳이 고르자면 **Encoding 키**를 권장. 앞뒤 공백이 섞여도 자동으로 잘라낸다.

### 5) 동작 확인
```bash
# 로그인 후 받은 토큰으로 호출 (이 API 는 로그인 필수)
curl -H "authorization: Bearer <세션토큰>" \
  "https://<도메인>/api/locations/building-info?address=경기 양평군 양평읍 양근리 120-5"
```
- 성공: `{"strctCdNm":"철근콘크리트구조","mainPurpsCdNm":...,"useAprDay":"..."}`
- `404`: 해당 지번에 대장이 없음(미등기·무허가) — 정상 동작, 앱은 촬영을 계속 허용한다
- 서버 로그에 `[BuildingRegistry] API 키가 설정되지 않아` → 환경변수 미반영(재배포 필요)
- 서버 로그에 `[BuildingRegistry] 지번 정보를 찾을 수 없습니다` → **카카오 키(2-2)** 문제

### 6) 운영계정 전환 (일 1,000건 초과 시)
1. 마이페이지 → 개발계정 → **운영계정 전환 신청**
2. 서비스 URL·활용 사례 기재 → 제공기관 심사 (통상 1~3일)
3. 승인되면 트래픽이 크게 늘어난다(서비스별 상이, 보통 일 10만건 수준)

> 파일럿 규모(일 수십 건)에서는 개발계정으로 충분하다.
> 서버가 6시간 캐시를 하므로 같은 주소를 반복 조회해도 쿼터를 쓰지 않는다.

## 5. 지금 알려진 제약

- **업체 수동 승인**: 가입 업체는 `PENDING` → 관리자가 승인해야 일감 수신. 자동화 미구현.
- **지역 매칭 범위**: 같은 시·군만 매칭된다. `경기 성남` 업체는 `경기 양평` 일감을 못 받는다.
  반경 기반으로 넓히려면 사업 정책 결정 후 `regionMatches` 정책을 바꾼다.
- **디몰비전 사진 업로드**: 요청당 최대 6장 분석(`MAX_ANALYZE_IMAGES`), 바디 12MB, 분당 10회.
- **건축물대장**: 미등기·무허가 건물은 조회되지 않는다(정상). 이때는 사용자가 직접 입력.
