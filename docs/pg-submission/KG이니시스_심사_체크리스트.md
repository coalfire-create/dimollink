# KG이니시스 가맹 심사 — 홈페이지·결제 점검표 (2026-10)

PG 를 토스페이먼츠에서 KG이니시스로 바꾸면서(사유는 `CLAUDE.md`「핵심 비즈니스 규칙」) 심사자가
홈페이지에서 확인하는 항목을 코드 기준으로 다시 점검했다. 값은 모두 `packages/shared` 한 곳
(`COMPANY_INFO`, `SALES_PRODUCTS`)에서 나오므로 앱 첫 화면·`/landing`·약관이 서로 어긋나지 않는다.

## 2. 이니시스 결제창 필수값 (포트원 V2 KG이니시스 문서 기준)

| 요구사항 | 코드 |
|---|---|
| 구매자 이름 필수 | `lib/portone-customer.ts` → 모든 결제·빌링 호출에 `customer` 전달 |
| 연락처·이메일 — **PC 결제 시 필수** | 연락처는 프로필 휴대폰, 이메일은 **소셜 로그인 이메일이 있을 때만** 넘어간다 ⚠️ |
| 가상계좌 입금기한 필수 | `VIRTUAL_ACCOUNT_VALID_HOURS`(24시간) |
| 빌링키 발급 `issueId` 필수 | `useStoreCheckout.ts` 에서 채번 |
| 모바일 빌링키 발급 `offerPeriod` 필수 | `{ interval: '1m' }` (월 정기결제만 판매) |
| 1,000원 미만 결제는 별도 계약 | 판매 상품은 모두 1,000원 이상 |

⚠️ **이메일:** 가입이 휴대폰 OTP 전용이라 대부분 회원에게 이메일이 없다. 그 상태로는 **PC 브라우저의
이니시스 결제창이 열리지 않을 수 있다.** 심사자는 보통 PC 에서 결제해 보므로, 심사 전에
가입·프로필 또는 결제 직전에 이메일을 받는 단계가 필요하다(미구현 — 결정 필요).

## 3. 전환 절차 (Railway 변수만 바꾼다 — 앱 재빌드 불필요)

1. 포트원 콘솔 → 채널 관리 → **KG이니시스 · 테스트 · V2** 채널 추가
2. Railway `PORTONE_CHANNEL_KEY` = 이니시스 테스트 채널 키, `PORTONE_ENV=test`
3. 웹(PC·모바일)과 앱에서 카드·가상계좌 결제 → 서버 검증 → 취소까지 전 구간 확인
4. 심사 통과 후 운영 MID 로 실연동 채널을 추가하고 키 교체 → `PORTONE_ENV=live`, `PORTONE_ALLOW_LIVE=true`
5. 정기결제는 이니시스 자동결제 계약(별도 MID) 후 `PORTONE_BILLING_CHANNEL_KEY` 설정

## 4. 제출 자료 주의

`이니시스_소명자료_답변서.md` 는 결제 대금을 "PG사 에스크로 예치"한다고 설명한다. 그런데
`CLAUDE.md` 의 확정 규칙은 **"에스크로 아님, 선결제 방식"** 이다. 제출 전에 실제 구조
(선결제 → 포트원 지급대행으로 D+1 정산)에 맞게 고칠지 확인한다 — 심사 자료와 실제 운영이
다르면 가맹 이후 문제가 된다.
