# KG이니시스 가맹 심사 — 홈페이지·결제 점검표 (2026-10)

PG 를 토스페이먼츠에서 KG이니시스로 바꾸면서(사유는 `CLAUDE.md`「핵심 비즈니스 규칙」) 심사자가
홈페이지에서 확인하는 항목을 코드 기준으로 다시 점검했다. 값은 모두 `packages/shared` 한 곳
(`COMPANY_INFO`, `SALES_PRODUCTS`)에서 나오므로 앱 첫 화면·`/landing`·약관이 서로 어긋나지 않는다.

## 2. 이니시스 결제창 필수값 (포트원 V2 KG이니시스 문서 기준)

| 요구사항 | 코드 |
|---|---|
| 구매자 이름 필수 | `lib/portone-customer.ts` → 모든 결제·빌링 호출에 `customer` 전달 |
| 연락처·이메일 — **PC 결제 시 필수** | 연락처는 프로필 휴대폰. 이메일이 없으면 **처음 결제할 때 한 번 묻고** 프로필에 저장(`BuyerEmailModal`) |
| 가상계좌 입금기한 필수 | `VIRTUAL_ACCOUNT_VALID_HOURS`(24시간) |
| 빌링키 발급 `issueId` 필수 | `useStoreCheckout.ts` 에서 채번 |
| 모바일 빌링키 발급 `offerPeriod` 필수 | `{ interval: '1m' }` (월 정기결제만 판매) |
| 1,000원 미만 결제는 별도 계약 | 판매 상품은 모두 1,000원 이상 |

**이메일:** 가입은 휴대폰 OTP 전용이라 대부분 회원에게 이메일이 없다. 그래서 스토어·매칭 결제에서
결제창을 열기 직전에 이메일을 한 번 받아 `PATCH /api/users/:id` 로 저장하고, 다음 결제부터는 묻지 않는다.

### 테스트 결제 결과 (2026-10-07, 이니시스 테스트 채널)

- PC Chrome·iPhone Safari: 결제창 정상. **PC Chrome 실결제 → `POST /api/products/demolition-membership/purchase` 200 → 이용권 발급** 확인.
- **PC(맥) Safari: 결제창이 `V901 잘못된 접근 방식입니다`로 바로 실패.** WebKit 엔진 문제(UA 를 바꿔도 동일).
  이니시스 PC 결제창은 iframe 만 지원해서(`windowType` POPUP·REDIRECTION 은 포트원이 거부) 코드로 우회할 수 없다.
  운영 MID 에서도 같은지 포트원/이니시스에 확인 필요.
- 테스트 MID 카드 결제는 실제 승인 후 당일 자동 취소되는 것으로 안내됨 — 다음 날 취소 반영을 확인한다.
- **포트원 웹훅 URL 이 사이트 루트(`/`)로 잡혀 404.** 콘솔에서 `https://www.디몰링크.com/api/payments/webhook` 으로 바꾸고
  `PORTONE_WEBHOOK_SECRET` 을 Railway 에 넣어야 가상계좌 입금 통지가 반영된다.

## 3. 전환 절차 (Railway 변수만 바꾼다 — 앱 재빌드 불필요)

1. 포트원 콘솔 → 채널 관리 → **KG이니시스 · 테스트 · V2** 채널 추가
2. Railway `PORTONE_CHANNEL_KEY` = 이니시스 테스트 채널 키, `PORTONE_ENV=test`
3. 웹(PC·모바일)과 앱에서 카드·가상계좌 결제 → 서버 검증 → 취소까지 전 구간 확인
4. 심사 통과 후 운영 MID 로 실연동 채널을 추가하고 키 교체 → `PORTONE_ENV=live`, `PORTONE_ALLOW_LIVE=true`
5. 정기결제는 이니시스 자동결제 계약(별도 MID) 후 `PORTONE_BILLING_CHANNEL_KEY` 설정

## 4. 제출 자료 정합성 (2026-10-06 정리)

`이니시스_소명자료_답변서.md`·`서비스_이용약관_공식본.md` 에 있던 "PG사 에스크로 예치", "에스크로 책임",
"분쟁 시 정산 즉시 동결", "㈜디몰링크" 표현을 실제 구조에 맞게 고쳤다 — **선결제 + 지급대행 정산이며
결제대금예치(에스크로) 서비스가 아니다**(`CLAUDE.md`). 코드에는 분쟁 신고(DISPUTE) 접수만 있고
자동 정산 보류는 없어서, 이행할 수 없는 약속을 지웠다.

남은 확인 사항: 소명서의 **입점업체 '플랫폼 보증금'**(전용 계좌·보증보험증권) 제도는 코드·로드맵에
없다. 실제로 운영할 계획이 없다면 제출 전에 그 항목을 빼야 한다.
